# Prisma Migration Workflow

## Rules
- All schema changes go through `packages/db/prisma/schema.prisma`.
- Never alter production tables manually.
- Migration SQL is generated by Prisma and committed.

## Local Development
1. Start database:
   - `npm run db:up`
2. Generate client:
   - `npm run db:generate`
3. Create/apply migration:
   - `npm run db:migrate -- --name <change_name>`
4. Seed realistic local data:
   - `npm run db:seed`
5. Check migration state:
   - `npm run db:migrate:status`

## CI / Deployment
- Deploy uses:
  - `npm run db:migrate:deploy`
- The app should start only after migration step succeeds.

## Rollback Guidance
- Preferred rollback is a forward-fix migration.
- Emergency rollback requires a manually reviewed SQL migration and backup restore strategy.
